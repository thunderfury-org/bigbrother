# Database Guidelines

> ORM patterns, queries, migrations, and data access conventions.

---

## ORM

**SeaORM 2.0.0-rc** with SQLite backend (`sqlx-sqlite`). Database is file-based, path from YAML config.

---

## Entity Layer

Auto-generated models live in `infrastructure/entity/model/`. Generated by `sea-orm-codegen` — **do not edit manually**.

Custom query functions live in sibling files under `infrastructure/entity/` (e.g., `file_index.rs`, `keyword.rs`). These contain the actual `find`, `insert`, `update` logic using SeaORM's `Entity::find()`, `ActiveModel` etc.

Current tables: `keyword`, `event`, `cache`, `file_index`, `file_location`, `file_description`, `file_location_description`.

---

## Repository Pattern

Repositories in `infrastructure/repo/` are **thin wrappers** that implement port traits from `application/ports.rs`. They delegate to entity query functions.

```rust
// infrastructure/repo/keyword.rs
pub struct SeaOrmKeywordRepository {
    db: DatabaseConnection,
}

#[async_trait]
impl KeywordRepository for SeaOrmKeywordRepository {
    async fn list_all_keywords(&self) -> AppResult<Vec<KeywordRecord>> {
        Ok(entity::keyword::list_all_keywords(&self.db).await?)
    }
}
```

**Rules**:
- Keep repo methods thin — real query logic belongs in `entity/*.rs` functions
- Repo's job: call entity function, convert `DbErr` → `AppError` via `?`
- Never expose SeaORM types beyond the infrastructure layer

## Migrations

**Crate**: `migration/` (workspace member)

- Uses `sea-orm-migration` with `MigratorTrait`
- Naming: `m{YYYYMMDD}_{HHMMSS}_{description}.rs` (e.g., `m20260506_000000_create_table_file_index.rs`)
- Register each migration in `migration/src/lib.rs` (`Migrator` derive)
- Run via `tools/migrate_db.sh` or during app startup

**Writing a migration**:
1. Create file following the naming convention
2. Implement `MigrationTrait` with `up` / `down`
3. Add to `Migrator` in `lib.rs`
4. Test with in-memory SQLite in repo tests

## Query Patterns

Use SeaORM's builder API, not raw SQL:

```rust
// Good — entity query function
pub async fn find_by_key(db: &DatabaseConnection, key: &str) -> AppResult<Option<keyword::Model>> {
    Ok(keyword::Entity::find()
        .filter(keyword::Column::Key.eq(key))
        .one(db)
        .await?)
}
```

---

## Test Database

Tests use in-memory SQLite with real migrations:

```rust
let mut options = ConnectOptions::new("sqlite::memory:");
options.sqlx_logging(false);
let db = Database::connect(options).await.unwrap();
Migrator::up(&db, None).await.unwrap();
```
